# Motion and scene ownership

- One primary R3F canvas, lazy imported after semantic HTML.
- Hero: ceramic signal seed, orbiting metadata connectors, mobile surfaces and discovery observatory. The seed unfolds through a DOM button, with raycast pointer interactions as enhancement.
- Desktop work: the same canvas is positioned in the active work viewport. Four semantic buttons select connector, discovery, build rotor or mobile machine. Each has a standard case-study URL.
- GSAP owns seed expansion and interruptible focus entrances. R3F owns rotations, pointer attraction and particle positions. Native scrolling controls stage placement through one throttled listener. No Lenis is required.
- Reduced motion freezes ambient motion, disables pointer following, removes scroll smoothing and uses zero-duration object transitions. The world is still usable, with the same DOM controls.
- The frame loop is demand-driven. It requests frames only while active and motion is allowed. Intersection and visibility observation stop ambient work outside the viewport/background tab.
- Quality uses viewport, memory, concurrency and save-data signals. Measured slow frames downgrade the scene. Blueprint toggles wireframe materials; Night Shift changes the DOM palette. These are optional user preferences, stored locally.
- All scene geometry is procedural. There are no downloaded GLB, HDR, or texture dependencies. Environment lighting uses local Lightformer geometry.

The remaining experience chapters are semantic HTML with a transit path, evidence connections, calm writing and contact sections. A full continuous cinematic camera traversal across all six chapters is not implemented.
